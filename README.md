# ⚡ ИИ-консультант для сайта ekt.kz

**HackAlem AI 2026 · трек «Торговля» · кейс ТОО «Электрокомплект»**

## Проблема
Чтобы узнать характеристики, сертификат, наличие или аналог, клиент ekt.kz пишет или звонит менеджеру.
Решение о покупке затягивается, часть клиентов уходит к конкурентам, менеджеры тратят время на однотипные вопросы.

## Решение
ИИ-агент в окне чата, который сам вызывает инструменты над каталогом:

| Must have | Как реализовано |
|---|---|
| Наличие, характеристики, сертификаты | `search_products`, `get_product` — данные только из каталога |
| Аналоги при нулевом остатке | `find_analogs` — та же категория, в наличии, с объяснением: что совпадает, что отличается, разница в цене |
| Условия покупки | `get_purchase_terms` — оплата, доставка, мин. партия, возврат |
| Корзина только после явного «да» | `propose_add_to_cart` → подтверждение клиента **отдельным сообщением** или кнопкой → `confirm_add_to_cart`. Проверка подтверждения, остатков и мин. партии — в коде |
| Ссылка на корзину | после добавления агент выдаёт ссылку `/?cart=<id>` с актуальным составом |
| Сопутствующие товары | `recommend_accessories`: к автомату — DIN-рейка и бокс, к кабелю — гофра; назначение и ограничения совместимости |
| Обращение к менеджеру | Кнопка «Позвать менеджера» и `request_manager`: сводка диалога, просмотренные товары, корзина и неподтверждённые предложения |
| Казахский язык | Автоопределение языка диалога и выбор «Қазақша»; ответы, кнопки подтверждения и сообщения при ошибках модели |

## Архитектура
```
Клиент (чат на сайте / Streamlit-демо)
        │
   ShopAgent (agent/agent.py) ── OpenAI function calling
        │
   Toolbox (agent/tools.py)
     ├── Catalog (agent/catalog.py) ── API ekt.kz  /  data/catalog_sample.json
     └── Cart   (agent/cart.py)     ── защита: propose → явное подтверждение → confirm
```

**Безопасность:** модель не может изменить корзину без подтверждения — это проверяет код, а не промпт.
Подтверждение должно прийти отдельным сообщением после предложения. Платёжные данные не запрашиваются и не хранятся.
Текст клиента и вложений воспринимается как данные, а не инструкции.

## Запуск
```bash
python -m venv .venv
.venv\Scripts\activate            # Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # Mac/Linux: cp .env.example .env — и заполните ключи
pytest -q
streamlit run app.py
```

В чате можно приложить спецификацию в XLSX, DOCX, PDF, JPG или PNG и нажать
«Проверить спецификацию». Документы читаются локально; фото распознаётся моделью
OpenAI с vision (`OPENAI_VISION_MODEL`, по умолчанию `OPENAI_MODEL`). Для каждой
найденной позиции проверяются данные каталога, а для товара с нулевым остатком — аналоги.
Файл не сохраняется на диск. Для распознавания фото нужен рабочий `OPENAI_API_KEY`.

Рекомендации используют только товары из загруженного каталога с достаточным остатком
для минимальной партии. В текущих демо-данных и локальной выборке сопутствующих товаров
нет: агент предложит категории без вымышленных артикулов и цен. После добавления
DIN-реек, боксов и гофры в каталог появятся конкретные предложения. Совместимость
по размерам, креплению и условиям монтажа требует отдельной проверки.

Кнопка «Позвать менеджера» готовит сводку в текущей сессии; её можно скачать в TXT
и передать через контакты сайта. Повторное нажатие обновляет то же обращение.
CRM, доставка уведомлений и подключение живого оператора пока не настроены;
интерфейс сообщает об этом. Сводка составляется без дополнительного вызова модели
и не включает служебный промпт или платёжные реквизиты.

## Данные
- `data/catalog_sample.json` — синтетическая выборка каталога со структурой полей из ТЗ
  (артикул, наименование, категория, характеристики, сертификаты, цена, остатки по складам).
- Для офлайн-демо укажите `EKT_API_USER` и `EKT_API_PASSWORD` в `.env`, затем выполните
  `.venv\Scripts\python.exe scripts/fetch_catalog.py --pages 5` (Linux/macOS: `.venv/bin/python`).
  Скрипт сохранит полные карточки в `data/catalog_cache.json`; при наличии этого файла
  `Catalog` читает его без запросов к API. Файл кэша не коммитится.
- Живой каталог: `USE_LIVE_API=1` в `.env` + логин/пароль API ekt.kz → `agent/catalog.py: load_from_api()`.
- `data/purchase_terms.json` — условия покупки (демо, заменить на реальные условия ekt.kz).

### Контракт API ekt.kz
- Реальные примеры: `data/api_sample_list.json` и `data/api_sample_detail.json`.
- Список возвращает `page`, `per_page`, `count`, `items`; `count` относится к текущей странице.
  Загрузчик запрашивает `?page=N`, по умолчанию не более пяти страниц (100 товаров).
- При поиске и открытии товара `Catalog` запрашивает `/products/detail?id=...`
  и кэширует карточку в памяти. Ошибка detail возвращается вызывающему коду;
  неполная карточка не выдаётся как товар с нулевым остатком.
- Артикул — `article`, цена — `price`, остатки — `stores[].quantity`;
  `quantity` используется только при отсутствии складов. Марка и минимальная
  партия — `properties.TORGOVAYA_MARKA` и `properties.KRATNOST_MIN`.
  Тип товара для сравнения аналогов — `properties.OBYEM`.
- В изученном ответе нет единицы измерения и сертификатов: эти поля остаются пустыми.
  Название товара 515291 содержит 160 А, а `NOMINALNYY_TOK` — 250 А:
  исходные значения сохранены без исправлений по догадке.
- Без локального кэша первичный поиск использует поля списка; характеристики доступны
  после подгрузки карточек. Для аналогов подгружаются карточки кандидатов из загруженных страниц.

## Диагностика реального каталога

Результаты проверки API, десять примеров исходных товаров и пять проверочных вопросов:
[CATALOG_DIAGNOSTICS.md](CATALOG_DIAGNOSTICS.md).
Текущий локальный кэш расширен до 470 полных карточек основных групп; это выборка
из 15 037 товаров API. Поиск учитывает бренд, ток и полюса (`1ф` / `1P`),
а отсутствие результата относится только к локальной выборке.
Агент использует до восьми раундов, последний — для итогового ответа;
ошибки инструментов логируются без текста исключений и секретов.
