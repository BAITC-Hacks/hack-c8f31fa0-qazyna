# ⚡ ИИ-консультант для сайта ekt.kz

**HackAlem AI 2026 · трек «Торговля» · кейс ТОО «Электрокомплект»**

## Проблема
Чтобы узнать характеристики, сертификат, наличие или аналог, клиент ekt.kz пишет или звонит менеджеру.
Решение о покупке затягивается, часть клиентов уходит к конкурентам, менеджеры тратят время на однотипные вопросы.

## Решение
ИИ-агент в окне чата, который сам вызывает инструменты над каталогом:

| Must have | Как реализовано |
|---|---|
| Наличие, характеристики, сертификаты | `search_products`, `get_product` — данные только из каталога |
| Аналоги при нулевом остатке | `find_analogs` — та же категория, в наличии, с объяснением: что совпадает, что отличается, разница в цене |
| Условия покупки | `get_purchase_terms` — оплата, доставка, мин. партия, возврат |
| Корзина только после явного «да» | `propose_add_to_cart` → подтверждение клиента **отдельным сообщением** или кнопкой → `confirm_add_to_cart`. Проверка подтверждения, остатков и мин. партии — в коде |
| Ссылка на корзину | после добавления агент выдаёт ссылку `/?cart=<id>` с актуальным составом |
| Сопутствующие товары | `recommend_accessories`: к автомату — DIN-рейка и бокс, к кабелю — гофра; назначение и ограничения совместимости |
| Обращение к менеджеру | Кнопка «Позвать менеджера» и `request_manager`: сводка диалога, просмотренные товары, корзина и неподтверждённые предложения |
| Казахский язык | Автоопределение языка диалога и выбор «Қазақша»; ответы, кнопки подтверждения и сообщения при ошибках модели |

## Архитектура
```
Клиент (чат на сайте / Streamlit-демо)
        │
   ShopAgent (agent/agent.py) ── OpenAI function calling
        │
   Toolbox (agent/tools.py)
     ├── Catalog (agent/catalog.py) ── CATALOG_SOURCE=cache | api | sample (явный выбор)
     ├── Cart   (agent/cart.py)     ── защита: propose → явное подтверждение → confirm
     ├── вложения (agent/attachments.py) ── XLSX / DOCX / PDF / фото
     └── обращение к менеджеру (agent/handoff.py) ── сводка текущей сессии
```

Streamlit (`app.py`) и HTTP-виджет (`server.py`, `static/`) используют общие модули агента.

**Безопасность:** модель не может изменить корзину без подтверждения — это проверяет код, а не промпт.
Подтверждение должно прийти отдельным сообщением после предложения. Платёжные данные не запрашиваются и не хранятся.
Текст клиента и вложений воспринимается как данные, а не инструкции.

## Запуск
Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните OPENAI_API_KEY в .env
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Linux/macOS:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Заполните OPENAI_API_KEY в .env
python -m pytest -q
python -m streamlit run app.py
```

В чате можно приложить спецификацию в XLSX, DOCX, PDF, JPG или PNG и нажать
«Проверить спецификацию». Документы читаются локально; фото распознаётся моделью
OpenAI с vision (`OPENAI_VISION_MODEL`, по умолчанию `OPENAI_MODEL`). Для каждой
найденной позиции проверяются данные каталога, а для товара с нулевым остатком — аналоги.
Файл не сохраняется на диск. Для распознавания фото нужен рабочий `OPENAI_API_KEY`.

Рекомендации используют только товары из загруженного каталога с достаточным остатком
для минимальной партии. В текущих демо-данных и локальной выборке сопутствующих товаров
нет: агент ничего не предлагает, включая категории вместо отсутствующих товаров. После добавления
DIN-реек, боксов и гофры в каталог появятся конкретные предложения. Совместимость
по размерам, креплению и условиям монтажа требует отдельной проверки.

Кнопка «Позвать менеджера» готовит сводку в текущей сессии; её можно скачать в TXT
и передать через контакты сайта. Повторное нажатие обновляет то же обращение.
CRM, доставка уведомлений и подключение живого оператора пока не настроены;
интерфейс сообщает об этом. Сводка составляется без дополнительного вызова модели
и не включает служебный промпт или платёжные реквизиты.

## Данные
- Для жюри используйте `CATALOG_SOURCE=cache` в `.env` (это значение по умолчанию).
  `data/catalog_cache.json` содержит 470 реальных карточек ekt.kz и хранится в репозитории.
  Если кэш отсутствует или повреждён, запуск завершается ошибкой, а не подменяет товары синтетическими.
- `CATALOG_SOURCE=api` выбирает API даже при наличии кэша; нужны `EKT_API_USER` и
  `EKT_API_PASSWORD`. При ошибке API допускается только реальный кэш; без него возвращается ошибка.
- `CATALOG_SOURCE=sample` — явно выбранный синтетический набор для разработки/тестов.
  **Не использовать перед жюри.** Старый `USE_LIVE_API` больше не управляет выбором источника.
- Для обновления кэша: `python scripts/fetch_catalog.py --pages N`.
  Это заменяет кэш первыми N страницами и может сузить выборку; перед показом проверьте артикулы из сценария.
- Сертификаты проверены рекурсивно во всех карточках кэша и `api_sample_detail.json`:
  ссылок на документы нет. Упоминание сертификатов в описании не является файлом сертификата.
  Результаты — `data/certificate_audit.json`. Агент честно сообщает об отсутствии документа
  в базе и предлагает «Позвать менеджера»; кнопка есть в Streamlit и HTML-виджете.
- `data/purchase_terms.json` содержит краткое изложение официальных страниц ekt.kz,
  поля `source`, `sources`, дату проверки и замечания. Противоречивый порог бесплатной
  доставки по Алматы, общий минимум заказа и индивидуальные оптовые условия требуют уточнения.
- [Сценарий на 3 минуты](DEMO.md) использует только артикулы реального кэша.

### Контракт API ekt.kz
- Реальные примеры: `data/api_sample_list.json` и `data/api_sample_detail.json`.
- Список возвращает `page`, `per_page`, `count`, `items`; `count` относится к текущей странице.
  Загрузчик запрашивает `?page=N`, по умолчанию не более пяти страниц (100 товаров).
- При работе без полного локального кэша `Catalog` запрашивает `/products/detail?id=...`
  и кэширует карточку в памяти. При сетевой ошибке detail он использует полную карточку
  из локального кэша, если она там есть, с предупреждением об актуальности остатка;
  неполная карточка не выдаётся как товар с нулевым остатком.
- Артикул — `article`, цена — `price`, остатки — `stores[].quantity`;
  `quantity` используется только при отсутствии складов. Марка и минимальная
  партия — `properties.TORGOVAYA_MARKA` и `properties.KRATNOST_MIN`.
  Тип товара для сравнения аналогов — `properties.OBYEM`.
- В изученном ответе нет единицы измерения и сертификатов: эти поля остаются пустыми.
  Название товара 515291 содержит 160 А, а `NOMINALNYY_TOK` — 250 А:
  исходные значения сохранены без исправлений по догадке.
- Без локального кэша первичный поиск использует поля списка; характеристики доступны
  после подгрузки карточек. Для аналогов подгружаются карточки кандидатов из загруженных страниц.

## Диагностика реального каталога

Результаты проверки API, десять примеров исходных товаров и пять проверочных вопросов:
[CATALOG_DIAGNOSTICS.md](CATALOG_DIAGNOSTICS.md).
Текущий локальный кэш расширен до 470 полных карточек основных групп; это выборка
из 15 037 товаров API. Поиск учитывает бренд, ток и полюса (`1ф` / `1P`),
а отсутствие результата относится только к локальной выборке.
Агент использует до восьми раундов, последний — для итогового ответа;
ошибки инструментов логируются без текста исключений и секретов.

## FastAPI и виджет для сайта

Сервер работает отдельно от Streamlit и использует тот же `ShopAgent` и каталог:

Windows PowerShell: `.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000`.

Linux/macOS: `python -m uvicorn server:app --host 127.0.0.1 --port 8000`
после активации виртуального окружения.

Заполните `OPENAI_API_KEY` в `.env`. Откройте демо: http://127.0.0.1:8000/.
Сам интерфейс находится в `static/widget.html`, загрузчик — в `static/widget.js`.
На любой странице подключите загрузчик одной строкой:

```html
<script src="http://127.0.0.1:8000/widget.js" async></script>
```

Для опубликованного сайта замените локальный адрес на HTTPS-адрес вашего сервера,
например `https://chat.example.kz/widget.js`. Если сайт использует CSP, разрешите
этот адрес в `script-src` и `frame-src`. Виджет работает в iframe на домене сервера:
запросы к API идут с того же origin, поэтому открывать CORS для всех сайтов не нужно.
Стили чата изолированы от страницы, размеры адаптируются в том числе к ширине 320px.

API:

- `POST /chat`: `{"message":"Есть автомат IEK 25А 1P?"}` создаёт сессию.
  Ответ содержит `session_id`, `answer`, `history`, `pending`, `cart`, `cart_url`.
- Следующие запросы передают полученный `session_id` и новое `message`.
  Неизвестная сессия возвращает 404; пустое или слишком длинное сообщение — 422.
- Кнопка «Да, добавить» отправляет отдельное сообщение `"Да, добавь"` и
  `proposal_id` из `pending`. Подтверждение выполняет `Cart.confirm()`:
  отрицание, нехватка остатков и повторное подтверждение не меняют корзину.
  Обычные текстовые `да` / `иә` обрабатываются агентом как в Streamlit.
- `GET /session/{session_id}` восстанавливает историю и ожидающие предложения.
- `GET /cart/{id}` показывает актуальный состав корзины; страница не кэшируется.
  Ссылки агента в этом сервере ведут сюда независимо от Streamlit `CART_BASE_URL`.

У каждой сессии отдельный агент и корзина, запросы одной сессии выполняются
последовательно. Идентификатор хранится в `sessionStorage` виджета; при запрете
хранилища чат работает до перезагрузки. Кнопка «Новый чат» создаёт новую сессию.
Ссылку на корзину может открыть любой, кому она передана.

Ограничение демо: сессии и корзины хранятся в памяти и пропадают при перезапуске.
Запускайте **один worker**; для нескольких процессов и долговременного хранения
понадобится общее хранилище сессий. Streamlit остаётся доступен через
`streamlit run app.py` со своим отдельным состоянием.

Проверка: `python -m pytest -q`. HTTP-тесты используют `httpx` и подменяют только
ответы модели; проверяют реальные `Toolbox` и `Cart`, отдельные сессии, подтверждение,
повторные/параллельные запросы, актуальность корзины и экранирование HTML.
